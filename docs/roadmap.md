# Roadmap

## MVP

- permission-based reading of existing events across Apple Calendar
- fresh Calendar reads on launch and every foreground transition
- Today, Last Week, and Last Month reviews compared with selected calendar
  categories
- local Complete/Incomplete status for every visible event
- evidence-based coaching with exactly seven suggestions or none
- server-managed OpenAI structured planning responses for the hosted iPhone
- stateless personal Railway deployment with authenticated status
- one-click confirmation of the complete seven-event batch
- live conflict/time-policy validation and default-calendar writes
- Apple Calendar-authoritative refresh after external edits
- two-tab Mark-1 and Progress interface with five-minute Mark-1 session reset
- check-ins, streak, and daily reminders

## Next

- Sign in with Apple and encrypted multi-device app-data sync
- CloudKit for app-owned notes/check-ins, not Calendar access
- restore a simplified Notes UI only after its role in coaching is redesigned
- notification-driven morning/evening review
- deterministic recurring-vs-one-off event classification and
  missed-frequency insights (FUTURE-001)
- additional device-data integrations only after a separate privacy/design
  review

## Later integrations

Guaranteed unattended server-side scheduling would require a separate product
and security design. It is not needed for the current Apple Calendar workflow,
which requires neither a secondary account nor a dedicated calendar.
